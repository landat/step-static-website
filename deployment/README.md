# Публикация и перенаправления meteorboxing.ru

Основная версия: **https://meteorboxing.ru/**, без `www` и `index.html`.

Проверено 5 ноября 2026 года: основной домен обслуживает nginx на Rusonyx,
а GitHub Pages — отдельная копия по адресу `https://landat.github.io/step-static-website/`.
До этой правки `robots.txt` и `sitemap.xml` на основном домене возвращали 404,
`www` и `index.html` возвращали 200, HTTP перенаправлялся на HTTPS.
Эти наблюдения сами по себе не устанавливают причину исключения из поиска.

**После публикации проверено на основном домене:** 76 из 76 HTTP-проверок прошли.
Все 19 соответствий из CSV работают, включая варианты старых разделов без `/`
и с `/index.html`; конечные страницы, robots.txt и sitemap.xml возвращают 200.
`www`, `index.html` и пустой `/?` перенаправляются настоящими 301 на основную версию.
Неизвестная страница возвращает 404, а `utm_source` сохраняется. Текущий Rusonyx
подхватил `.htaccess` через существующее автоматическое обновление: для этих
перенаправлений отдельное ручное включение nginx больше не требуется.

## Где находятся файлы

Исходники и готовые страницы: https://github.com/landat/step-static-website/tree/main

- `index.html`, `*.html` — готовые страницы.
- `assets/` — оформление, изображения, видео и скрипты.
- `content/site.json` — редактируемые данные CMS, включая статьи.
- `admin/` — панель тренера.
- `.htaccess`, `robots.txt`, `sitemap.xml` — настройки Apache и индексации.
- `deployment/redirect-map.csv` — соответствия прежних и новых адресов.
- `deployment/nginx-redirects.conf` — серверные правила для nginx.

Физическую папку на Rusonyx нужно смотреть в настройках **сайта meteorboxing.ru**
в панели хостинга: поле «Корневая директория» / «Document root» и файловый менеджер.
Название папки зависит от панели и тарифа. Путь GitHub не является путём на сервере;
не подставляйте предполагаемый `httpdocs` или `www` без проверки настройки домена.

## Автоматическое обновление

**Статус:** готовые HTML для этой публикации собраны. Новая автоматическая сборка
подготовлена в `deployment/publish-site.workflow.yml`, но пока не установлена:
GitHub отклонил её запись через OAuth без `workflow` scope, а GitHub-интеграция
вернула `Resource not accessible by integration`. Обычная синхронизация Rusonyx
с GitHub при этом сохраняется.

Для разовой активации владелец репозитория создаёт в интерфейсе GitHub файл
`.github/workflows/publish-site.yml` с содержимым подготовленного файла, затем
в **Settings → Pages → Source** выбирает **GitHub Actions** и запускает workflow.
Передавать токен или пароль разработчику для этого не нужно. До активации после
добавления статей или изменения статических SEO-полей нужно выполнить ручную сборку
ниже и опубликовать результат. Тексты существующих страниц продолжают обновляться
из JSON в браузере, как прежде.

После активации сохранение в CMS меняет `content/site.json` в GitHub. Workflow **Build and publish site**
собирает HTML, включая новые статьи и SEO-поля, и сохраняет готовые страницы в `main`.
Их забирает уже настроенное владельцем автоматическое обновление Rusonyx.
Тот же workflow публикует отдельную копию на GitHub Pages.

Нужно проверить, что существующее обновление Rusonyx включает **новые HTML-файлы,
`robots.txt`, `sitemap.xml` и скрытый файл `.htaccess`**, а не только ранее известные файлы.
В GitHub не добавлены пароли хостинга. Если синхронизация использует архив с GitHub Pages,
он должен содержать результат сборки; запросы к GitHub Pages сами не исполняют `.htaccess`.

После сохранения дождитесь зелёного workflow и затем обновления Rusonyx. Проверяйте
результат на **meteorboxing.ru**, а не только на GitHub Pages.

## Активация настоящих 301

На текущем хостинге правила уже проверены. При переносе на другой тариф/сервер
выберите вариант по его настройкам. Правила нельзя считать включёнными, пока
старый URL не вернул HTTP 301 с правильным заголовком `Location`.

### Apache за nginx

Сохраните копию существующего `.htaccess`. Добавьте подготовленные правила из корня
репозитория **перед** правилами старого конструктора/CMS. Не удаляйте посторонние настройки
хостинга и SSL. Проверьте, что Apache действительно получает запросы к старым адресам,
`index.html` и статическим страницам: nginx может обслуживать их самостоятельно.
GitHub Pages этот файл не исполняет.

### nginx обслуживает сайт самостоятельно

Включите `deployment/nginx-redirects.conf` в блоки `server` домена и `www`,
перед общим HTTP→HTTPS / www-перенаправлением. Это фрагмент, а не замена всей конфигурации:
существующие пути к файлам и сертификатам нужно сохранить. Администратор проверяет
`nginx -t` и применяет конфигурацию. При отсутствии доступа к конфигурации передайте
этот файл поддержке Rusonyx. Не помещайте его в `.htaccess`.

Сертификат должен покрывать и основной домен, и `www`: HTTPS-соединение происходит
до получения редиректа.

## Проверка после публикации

Ожидаемые ответы (проверять без автоматического следования редиректам):

| Запрос | Ответ | Location |
| --- | --- | --- |
| `https://meteorboxing.ru/` | 200 | — |
| `http://meteorboxing.ru/about.html` | 301 | `https://meteorboxing.ru/about.html` |
| `https://www.meteorboxing.ru/about.html` | 301 | `https://meteorboxing.ru/about.html` |
| `https://meteorboxing.ru/index.html` | 301 | `https://meteorboxing.ru/` |
| `/o-nas/` | 301 | `https://meteorboxing.ru/about.html` |
| `/trenirovki/gruppovye-trenirovki/` | 301 | `https://meteorboxing.ru/group-training.html` |
| `/trenirovki/individualnye-trenirovki/` | 301 | `https://meteorboxing.ru/personal-training.html` |
| `/stati/` | 301 | `https://meteorboxing.ru/articles.html` |
| Прежний адрес конкретной статьи | 301 | Адрес этой статьи из CSV |
| `/robots.txt`, `/sitemap.xml` | 200 | — |
| Неизвестная удалённая страница | 404 | — |

Правила также покрывают старые разделы без завершающего `/` и с `/index.html`.
Пустой параметр `/?` перенаправляется на `/`; настоящие метки `?utm_source=...`
сохраняются для аналитики. Их канонический адрес указан без параметров.
Некоторые клиенты удаляют пустой `?` ещё до отправки. Для точной проверки:

```sh
curl --request-target '/?' -I https://meteorboxing.ru/
```

После проверки отправьте `https://meteorboxing.ru/sitemap.xml` в Яндекс Вебмастер
и Google Search Console, проверьте причины исключения конкретных старых и новых URL
и запросите переобход важных страниц. Отправка карты и 301 не гарантируют сроков
или самого включения каждой страницы в индекс. При неизвестных старых URL дополните
CSV-источник `content/redirects.json` данными Вебмастера, Search Console или логов сервера.

## Ручная сборка

```sh
npm ci
npm run build:cms
npm test
npm run sync:publication
```

Готовый каталог — `dist/`. Публикуйте его содержимое в подтверждённую корневую папку
домена. Не загружайте `node_modules`, `.git` и тестовые данные. Перед заменой существующих
файлов сохраните их резервную копию средствами хостинга.

## Источник старых адресов и статей

Разделы и четыре статьи восстановлены из снимков старого сайта в Internet Archive,
начиная с https://web.archive.org/web/20241206174255/https://meteorboxing.ru/ .
Первоначальные даты статей: 2014, 2017 и 2018 годы; они сохранены, а материалы отмечены
как архивные. Не утверждается, что архив содержит все адреса за все годы существования сайта.

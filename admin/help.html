Как обновить сайт МЕТЕОР

Панель работает на Sveltia CMS. Оплачивать CMS, отдельный сервер или домен не нужно.

Первый вход

Попросите разработчика помочь с первоначальной настройкой. Нужна ваша учётная запись GitHub с правом записи в репозиторий landat/step-static-website.

  1. Примите приглашение в репозиторий, если разработчик его отправил.
  2. Создайте токен доступа в своей учётной записи GitHub по инструкции ниже.
  3. Откройте панель управления и нажмите «Войти с помощью токена доступа».
  4. Вставьте токен и выполните вход. В этом браузере он сохраняется для последующих посещений.

Токен — как пароль. Не отправляйте его в переписку, не добавляйте в файлы сайта и не используйте чужой токен. Входите на своём устройстве. После окончания срока токена нужно создать новый и войти повторно.

Настройка токена — для разработчика

Владелец репозитория: создайте fine-grained token, выберите только step-static-website и разрешение Contents: Read and write. Metadata: Read добавляется автоматически. Выберите ограниченный срок, например 90 дней. Pull requests и Workflows для редактирования через эту панель не нужны.

Тренер с отдельной учётной записью: fine-grained токены GitHub пока не поддерживают запись в чужой личный репозиторий для приглашённых collaborators. Для этого публичного репозитория используйте classic token с областью public_repo в учётной записи тренера и сроком, например 90 дней. Эта область распространяется на все публичные репозитории, доступные его аккаунту, а не только на этот сайт. Области repo и workflow не требуются. Если репозиторий станет приватным, схему доступа нужно пересмотреть.

Токен не заменяет приглашение: учётная запись должна иметь право записи. Не выдавайте тренеру токен владельца. Документация GitHub о токенах и ограничениях.

Изменить текст или расписание

  1. Откройте «Содержимое сайта» → «Объявление, расписание и другие разделы».
  2. Разверните нужный раздел: объявление, расписание, новости, фотографии, контакты, цены, видео или материалы.
  3. Измените поля. В списках можно добавлять, удалять и переставлять элементы; переключатель «Показывать на сайте» временно скрывает карточку.
  4. Нажмите «Сохранить». Подождите публикации GitHub Pages, обычно несколько минут, затем обновите страницу сайта.

Все разделы сохраняются вместе. Не редактируйте сайт одновременно в двух вкладках или в старой CMS. Если панель сообщает о конфликте, обновите данные и повторите изменения.

Фотографии, видео и документы

В поле файла нажмите кнопку выбора, затем загрузите файл или выберите существующий. Фотографии: JPG, PNG, WebP; видео: MP4, WebM; документы: PDF, DOC, DOCX. Лимит загрузки в этой панели — 50 МиБ на файл. Для больших видео используйте Rutube.

К фотографии добавьте подпись. У видео выберите тип «Загруженный MP4/WebM» или «Rutube» и заполните соответствующее поле. Для документа добавьте название, текст и при необходимости файл.

Новые фотографии автоматически обрабатываются существующей задачей после загрузки в GitHub. Для ручного сжатия нажмите «Уменьшить большие фотографии» вверху панели, затем на GitHub выберите Run workflow → main → Run workflow. Дождитесь зелёной отметки выполнения.

Если что-то не работает

  • Ошибка входа: проверьте срок токена, область доступа и принятие приглашения.
  • Панель открылась, но данные не загрузились: проверьте доступность api.github.com и сообщите разработчику текст ошибки.
  • Сайт не изменился: подождите 5 минут, обновите его через Ctrl+F5 и проверьте публикацию GitHub Pages.
